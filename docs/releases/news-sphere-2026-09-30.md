For a production withdrawal, first fetch and create an isolated checkout from the
current remote main, preserving any intervening changes. With a clean index:

```sh
git revert 154b68492f0de2764451117bd68548d07be54a01
npm run check
npm run lint
npm run test:unit
npm run test:news:render
npm run build
npm run test:smoke
```

This is the only functional dependency to withdraw. Keep this audit record;
it is not runtime code. Do not reset, force-push or restore the whole repository.
If revert conflicts, stop and retain the conflict state for review. Once checks
pass, push the new revert commit normally and verify its Pages result and public
reader/follows/saved-data behavior. Re-enabling after a committed withdrawal means
reverting the actual withdrawal commit, not restoring an old repository snapshot.
