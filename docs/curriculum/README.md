## 分类约定

每项材料有一个主要主题；通过 `relatedTopics` 建立交叉关联。主题主线与材料载体分开：

- `domainId` / `topicId`：知识归属，不由原文件夹自动决定。
- `role`：正文、目录、实验、注释源码、参考资料、案例、交互图或维护资源。
- `layer`：总览、原理、运行时、平台实现、实验、参考、综合案例或图表。
- `difficulty`：入门、进阶、深入，属于编辑判断。
- `prerequisites`：建议先理解的主题，允许材料级覆盖。不是访问限制，也不是必须读完该主题的全部文章。
- `platformScope`：涉及的平台或示例依赖；`general` 表示通用机制，`cpu` 表示 CPU 数学示例，`pytorch` 等表示代码依赖。它不是平台兼容性认证。
- `sources` / `availableLanguages`：实际存在的中英文文件与 Git blob。英文目录中的中文注释源码会单独说明，不视为已完成英文翻译。
- `versionEvidence`：从正文提取的固定 revision 链接；它们可能对应背景论文、对照实现或主要实现，统一标记待逐篇核对，不自动认定为该课唯一源码基线。没有直接链接也不代表正文没有版本信息。
- `existingSiteRoute`：从固定网站索引复制的旧链接；没有索引时为 `null`，不臆造新路由。
- `siteCopy`：逐语言比较固定 Git blob。`different` 只表示内容不同，不能自动覆盖网站已有编辑；`missing` 表示该文件未在网站副本中找到。
- `status=source-present` / `verification=catalog-only-no-execution`：本轮确认文件存在并完成目录校验，没有执行教程中的硬件实验。

`planned` 独立列出 16 个计划文件，并链接原路线图证据与同主题已有材料。计划文件缺失不代表同一知识点没有其他讲解；这些条目不能出现在“已完成课程”统计或学习路线必读步骤中。

## 维护与校验

不需要访问网络，不需要 API Key。使用已有教程仓库路径；生成器读取固定 Git 对象，不读取该仓库工作区的未提交正文，也不会执行其中的代码。

```sh
node scripts/curriculum-plan.mjs --source /path/to/SGLang_Tutor
node scripts/curriculum-plan.mjs --source /path/to/SGLang_Tutor --check
node --test tests/curriculum-plan.test.mjs
```

首次生成写入 `catalog.json` 与 `catalog.md`。`--check` 只核对可复现结果，不修改文件。脚本不下载源码、不切换分支、不调用现有同步脚本，不收录机器路径。新源码版本出现未分类文件时会失败，要求编辑明确归类；不按父目录静默猜测。

更新基线时先审核新旧版本差异，再修改 `plan.mjs` 中的 SHA 和人工分类规则。原材料 ID 由稳定源路径生成；源仓库发生改名时必须人工记录映射，不能因标题相似而自动合并。
